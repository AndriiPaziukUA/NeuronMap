# NeuronMap

NeuronMap — настільний застосунок на JavaFX для створення, редагування та запуску симуляції карт нейронів. Нейрони можна з'єднувати, налаштовувати та об'єднувати в групи. Програма зберігає карти локально й дозволяє повертатися до попередніх змін.

Цей файл допомагає зорієнтуватися в коді, запустити програму та зрозуміти, куди вносити зміни.

## Що потрібно для роботи

- JDK 21;
- Windows або інша система, на якій доступний JavaFX для обраного середовища.

У репозиторії є Maven Wrapper, тому окремо встановлювати Maven не обов'язково. Переконайся, що `java -version` використовує JDK 21.

## Запуск і перевірка

У корені проєкту виконай відповідні команди.

Windows PowerShell:

```powershell
# Запустити всі тести
.\mvnw.cmd clean test

# Запустити застосунок
.\mvnw.cmd javafx:run
```

Linux/macOS:

```bash
# Запустити всі тести
./mvnw clean test

# Запустити застосунок
./mvnw javafx:run
```

Якщо Maven уже встановлено, можна використовувати `mvn clean test` і `mvn javafx:run`. Під час `test` Maven також формує звіт покриття JaCoCo в `target/site/jacoco/`, якщо виконання дійшло до етапу звіту.

Якщо тести падають, спочатку прочитай повідомлення першої помилки: наступні помилки нерідко є її наслідком. Після зміни коду запускай повний набір тестів.

## З чого почати читання коду

Для першого знайомства радимо йти таким шляхом:

1. `app/NeuronMapApp.java` — запуск застосунку та складання його компонентів.
2. `application/NeuronMapApplicationService.java` — створення служб, які виконують основні операції.
3. `model/` — дані нейронів, зв'язків, груп і карти.
4. `service/` — операції над моделлю та проєктами.
5. `simulation/` — правила поширення сигналів і синхронізація тактів.
6. `persistence/` — завантаження та збереження даних.
7. `controller/` і `view/` — реакція на дії користувача та візуальне відображення.
8. `coordinator/` — порядок взаємодії кількох компонентів.
9. `project/` і `settings/` — типи проєктів і спільна логіка сеансу редагування налаштувань.
10. `src/test/java/` — приклади перевірок очікуваної поведінки.

Докладніші правила поділу відповідальностей наведені в [архітектурному довіднику](docs/ARCHITECTURE.md), а команди та призначення тестів — у [довіднику тестування](docs/TESTING.md). У самих Java-файлах опис класів і методів міститься безпосередньо над відповідними оголошеннями.

## Основні правила архітектури

- **Модель** описує дані й правила карти, але не залежить від JavaFX.
- **Служби** виконують операції над моделлю та координують доступ до сховища через його контракт.
- **Симуляція** обчислює поширення сигналів і такти; її можна тестувати без відкриття вікна.
- **Контролери** реагують на події інтерфейсу та викликають потрібні служби.
- **Відображення** відповідає за вигляд і розташування елементів, а не за збереження даних.
- **Координатори** задають порядок взаємодії компонентів, але не замінюють служби й не дублюють їхню логіку.
- **Збереження** зосереджене в `persistence`; SQL не повинен з'являтися в контролерах або компонентах відображення.

У головному меню `MainMenuView` складає спеціалізовані подання головної сторінки, списку проєктів і вибору мови. `MainMenuController` керує навігацією та життєвим циклом незбережених змін.

Для відкату налаштувань у проєкті є два окремі API: `controller.SettingsEditSession`, який зараз використовує головне меню через `Participant`, та узагальнений `settings.SettingsEditSession`, який працює з типізованими значеннями й callback-ами. Це різні класи; узагальнений клас сам собою не підключається до сесії головного меню. Перед додаванням налаштувань перевір, який саме механізм відповідає за відповідний сценарій.

Якщо правило можна перевірити без створення JavaFX-вікна, зазвичай його варто розмістити в моделі, службі або пакеті симуляції, а не в контролері.

## Де зберігаються проєкти

Застосунок використовує каталог `Documents/NeuronMap` у домашньому каталозі поточного користувача. Кожен збережений проєкт має власну папку з файлом `project.db`. Папка без цього файлу не вважається збереженим проєктом.

Новий порожній проєкт спочатку існує в пам'яті. Дані записуються на диск, коли проєкт справді потрібно зберегти. Загальні налаштування застосунку та розташування вікна зберігаються окремо від даних конкретної карти.

## Як вносити зміни

1. Знайди відповідальний пакет за таблицею вище та прочитай документацію класу й потрібних методів.
2. Внось правило в той шар, якому воно належить; не перенось бізнес-логіку в контролер заради зручності.
3. Додай або зміни тест, який описує очікувану поведінку.
4. Запусти `clean test` через Maven Wrapper або Maven.
5. Перевір, чи не порушено межі шарів і чи не з'явилося дублювання логіки.

Для конкретних прикладів дивись на тести поруч із відповідним пакетом. Вони фіксують не лише звичайний сценарій, а й важливі крайові випадки.
