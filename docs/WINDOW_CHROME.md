# Власне оформлення головного вікна

## Основний механізм

Проєкт використовує JDK 25 LTS та JavaFX 27. Якщо поточний JavaFX toolkit підтримує `ConditionalFeature.EXTENDED_WINDOW`, головне вікно створюється зі стилем `StageStyle.EXTENDED`. Це штатний API JavaFX для розширення клієнтської області у системну смугу заголовка, а не ручна імітація заголовка через `StageStyle.UNDECORATED`.

`view/window/WindowChromeView` і далі відповідає за вигляд власного заголовка та локалізовані підписи кнопок. Метод `installExtendedHeaderBar()` поміщає наявну смугу в `javafx.scene.layout.HeaderBar`, вимикає стандартну смугу системних кнопок через `HeaderBar.setSystemButtonHeight(stage, 0)` і задає семантичні ролі власним кнопкам:

- `HeaderButtonType.ICONIFY` — згортання;
- `HeaderButtonType.MAXIMIZE` — максимізація/відновлення із системною поведінкою платформи, включно з Snap Layouts там, де це підтримує Windows;
- `HeaderButtonType.CLOSE` — закриття через стандартний життєвий цикл `Stage`.

Вільні області заголовка позначаються через `HeaderDragType`, тож JavaFX самостійно обробляє переміщення та нативну взаємодію заголовка. Застосунок не малює смугу зміни розміру, не відводить під неї внутрішні пікселі вікна й не перехоплює `WM_NCCALCSIZE` або `WM_NCHITTEST` у цьому режимі. Нативна геометрія рамки та resize залишається відповідальністю віконного toolkit і Windows.

`HeaderBar` розташовується на всю ширину верхньої області сцени. У ньому використовуються наявні кнопки та їхні стилі з `src/main/resources/window-chrome.css`; окремі копії кнопок або паралельна логіка керування станом `Stage` не створюються. Для кнопок залишаються системні семантичні типи, а не ручний переклад координат у коди Win32.

## Межі архітектури

`window` містить платформонезалежні типи геометрії та контракт команд заголовка. `WindowChromeView` реалізує контракт `WindowChrome`, але не залежить від Win32.

`app/WindowChromeLifecycle` перевіряє можливість `EXTENDED_WINDOW` до показу вікна. Якщо функція підтримується, він ініціалізує `StageStyle.EXTENDED` і встановлює JavaFX `HeaderBar`; фабрика платформних адаптерів у цьому сценарії не викликається. Це дозволяє Windows, Linux і macOS використовувати спільний механізм без розростання контролера ОС-специфічними умовами.

`windowing/WindowPlatformAdapter` та його наявні реалізації залишаються резервним шляхом для JavaFX-середовищ, де `EXTENDED_WINDOW` не підтримується. У такому режимі життєвий цикл повертається до попереднього адаптерного підходу. Це не основний шлях для JavaFX 27 на Windows, Linux і macOS. Нову платформу спочатку слід перевіряти через `Platform.isSupported(ConditionalFeature.EXTENDED_WINDOW)` і використовувати нативний заголовок JavaFX, якщо toolkit його надає.

`MainWindowController` залишається власником `Stage`, збереження геометрії та команд завершення. Натискання вбудованої кнопки закриття викликає стандартне закриття `Stage`, яке проходить через чинний `WINDOW_CLOSE_REQUEST` і наявний `WindowLifecycleCoordinator`. Геометрія продовжує зберігатися через `WindowStateStore`.

## Локалізація та стилі

Базовий набір підписів заголовка розміщено в `src/main/resources/i18n/windowChrome.properties`. `WindowChromeView` використовує спільну `LocalizationService` і оновлює доступні назви кнопок при зміні мови. Окремі англомовні копії базових ресурсів не потрібні: для англійської `LocalizationService` використовує базові properties-файли.

Стилі власного заголовка та його кнопок визначені в `src/main/resources/window-chrome.css`. CSS описує тільки видимий вміст. Він не задає hit-test меж, не додає внутрішній padding для resize та не намагається імітувати системну зовнішню рамку. Відсутність рамки не досягається приховуванням її малювання після ручної підміни WndProc: у головному режимі за неї відповідає системний механізм JavaFX.

## Перевірка на Windows

Після `./mvnw clean test` перевір застосунок на Windows 10/11. Особливо важливо перевірити на реальному нативному вікні:

- зміну розміру за всіма чотирма краями та кутами, коли курсор ще трохи не дійшов до видимої межі;
- відсутність внутрішньої смуги resize, рамки або миготливого неклієнтського контуру;
- переміщення вікна за вільну область заголовка та подвійне клацання для максимізації;
- згортання, максимізацію/відновлення, закриття та збереження геометрії;
- Snap Layouts наведенням на кнопку максимізації в Windows 11;
- масштаби дисплеїв 100%, 125% і 150%, а також перетягування між моніторами з різним DPI.

JavaFX `HeaderBar` є системним API, але остаточний результат слід підтвердити на цільових ОС та драйверах. Unit-тести перевіряють вибір режиму, конфігурацію семантичних кнопок і те, що вбудований режим не створює ручного платформного адаптера; вони не замінюють перевірки реального resize Windows.
