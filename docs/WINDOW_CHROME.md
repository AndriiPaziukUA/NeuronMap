# Власне оформлення головного вікна

## Єдиний механізм системної взаємодії

NeuronMap використовує JDK 25 та JavaFX 27. Головне вікно створюється зі стилем `StageStyle.EXTENDED`, а власний заголовок розміщується в `javafx.scene.layout.HeaderBar`. Перед налаштуванням застосунок перевіряє `Platform.isSupported(ConditionalFeature.EXTENDED_WINDOW)`. Якщо можливість недоступна, конфігурація завершується явною помилкою: резервний адаптер або інший стиль вікна не запускається.

JavaFX 27 підтримує `ConditionalFeature.EXTENDED_WINDOW` на Windows, Linux і macOS. На цих ОС NeuronMap використовує той самий механізм системної взаємодії, а не окремі реалізації Win32, AppKit чи X11. `EXTENDED_WINDOW` усе одно перевіряється під час запуску, щоб не покладатися лише на назву ОС. Зауваж: у переліку платформ офіційного JavaFX 27 зазначено Windows x86_64, Linux x86_64 та macOS AArch64; для інших архітектур потрібна сумісна збірка JavaFX.

JavaFX відповідає за інтеграцію заголовка з віконною системою, переміщення, системну зміну розміру та семантику кнопок. У `WindowChromeView.installExtendedHeaderBar()` власним кнопкам задаються системні ролі:

- `HeaderButtonType.ICONIFY` — згортання;
- `HeaderButtonType.MAXIMIZE` — максимізація та відновлення;
- `HeaderButtonType.CLOSE` — штатне закриття `Stage` через `WINDOW_CLOSE_REQUEST`.

Смуга заголовка допускає перетягування, але кнопки виключені з перетягуваної області за допомогою `HeaderDragType.NONE`. Застосунок не підміняє системну процедуру вікна й не реалізує ручний hit-testing.

## Платформні стилі

`WindowChromePlatformStyle` централізовано визначає візуальний варіант за системною властивістю `os.name`. Він впливає тільки на компонування заголовка, CSS-клас кореневого вузла й необов'язкову додаткову таблицю стилів. Цей вибір не змінює системного механізму керування вікном.

- **Windows:** використовує базовий `window-chrome.css`; квадратні кнопки розташовані праворуч, займають усю висоту смуги заголовка й доходять до її верхнього та правого країв без вертикального проміжку.
- **Linux:** використовує спільні стилі та `window-chrome-linux.css`; квадратні кнопки розташовані праворуч і так само заповнюють висоту заголовка. Linux-стиль змінює вигляд наведення та радіус кутів, а не геометрію кнопок.
- **macOS:** використовує спільні стилі та `window-chrome-macos.css`; кнопки розташовані ліворуч у звичному для macOS порядку, залишаються компактними круглими індикаторами й мають навмисні відступи від країв. Назва геометрично центрується незалежно від ширини групи кнопок. Довгу назву обмежено симетричною вільною областю, щоб вона не накладалася на кнопки. Доступна назва й значок зеленої кнопки відповідають входу або виходу з повноекранного режиму; стан звичайної максимізації не перемикає значок повноекранної дії.
- **Інші ОС:** використовують стандартне компонування й базову таблицю стилів, якщо JavaFX підтримує `EXTENDED_WINDOW`.

Спільна геометрія кнопок Windows і Linux визначається в базовому `window-chrome.css`: ширина та висота дорівнюють `WindowChromeView.TITLE_BAR_HEIGHT`. Вертикальні відступи контейнера заголовка нульові. Для кнопок також перевизначено стандартні відступи шарів фону й рамки та вимкнено ефекти, щоб базове оформлення JavaFX не створювало однопіксельного виступу або тіні за межами кнопки. CSS macOS явно перевизначає розміри для збереження круглих індикаторів; їхні відступи є частиною дизайну, а не випадковою щілиною.

`WindowChromeView` зберігає спільну поведінку кнопок, локалізацію та спостереження за станом `Stage`. `WindowChromeIconFactory` створює геометрію векторних значків і задає їм спільні властивості полотна; фабрика не залежить від `Stage`, локалізації чи життєвого циклу сцени. `WindowChromePlatformStyle` не створює окрему реалізацію керування вікном: він ізолює лише платформні візуальні відмінності. Щоб додати нову візуальну схему, достатньо доповнити централізований вибір стилю та додати відповідний CSS-ресурс, не змінюючи `MainWindowController` чи `WindowChromeLifecycle`. Окремий системний механізм потрібен лише тоді, коли майбутня платформа не підтримуватиме стандартний API JavaFX або вимагатиме іншої системної інтеграції.

Спільні стилі містяться в `src/main/resources/window-chrome.css`, стилі macOS — у `src/main/resources/window-chrome-macos.css`, Linux — у `src/main/resources/window-chrome-linux.css`. Базові стилі залишаються спільними, а платформні файли містять лише необхідні відмінності. Назви кнопок для допоміжних технологій беруться зі спільної `LocalizationService` та ресурсів `i18n/windowChrome*.properties`.

## Межі відповідальності

`MainWindowController` володіє `Stage`, відновленням геометрії та завершенням редактора. `WindowChromeLifecycle` перевіряє підтримку `EXTENDED_WINDOW`, установлює один стиль вікна, додає подання заголовка й керує його очищенням. `WindowChromeView` відповідає за структуру заголовка, локалізовані назви та відображення стану кнопок; пакетний `WindowChromeIconFactory` ізольовано створює геометрію їхніх векторних значків, а `WindowChromePlatformStyle` визначає платформне оформлення.

Встановлення подання спочатку перевіряє обов'язкові CSS-ресурси, а потім змінює корінь сцени. Під час очищення подання повертає початковий корінь лише тоді, коли сцена досі використовує саме це подання; корінь, установлений іншим компонентом, не перезаписується. Таблиці стилів видаляються лише тоді, коли їх додало саме подання. Повторно встановити екземпляр після успішного `dispose()` не можна; це відхиляється до зміни сцени. Якщо очищення подання не вдалося, `WindowChromeLifecycle` зберігає посилання та обробник приховування для наступної спроби. У разі помилки незалежні кроки очищення виконуються окремо, а помилки не маскуються.

Пакети `com.example.neuronmap.window` і `com.example.neuronmap.windowing`, ручний Win32 `WndProc`, JNA-адаптери й ручний hit-testing не використовуються. `persistence/window` залишається, бо відповідає за збереження геометрії вікна, а не за оформлення заголовка.

## Перевірка

Запусти `./mvnw clean test` (у Windows — `.\mvnw.cmd clean test`). Окремо перевір на реальних цільових ОС:

- переміщення вікна за вільну область заголовка;
- зміну розміру за краями та кутами;
- згортання, максимізацію/відновлення, закриття й збереження геометрії;
- квадратні кнопки Windows/Linux без верхнього проміжку та з приляганням кнопки закриття до правого краю; круглі кнопки macOS зі збереженими відступами;
- масштаби дисплея 100%, 125% і 150%, а також перетягування між моніторами з різним DPI;
- інтеграцію системних можливостей конкретного середовища, зокрема Snap Layouts у Windows 11.

Тести перевіряють вибір стилю для назв ОС, фактичні межі центрованої назви після CSS/layout, відсутність накладання довгої назви на кнопки macOS, тип значка повноекранного режиму, геометрію та розташування кнопок Windows/Linux, платформно коректні доступні назви, системні ролі кнопок, перетягувану область, відхилення повторного встановлення після очищення, обробку непідтримуваного середовища, повернення сцени до початкового стану й збереження сторонньої заміни кореня. `WindowChromeIconFactoryTest` окремо перевіряє геометрію, стилі й розміри векторних значків. GitHub Actions запускає `clean test` на Windows, Linux (із Xvfb) та macOS з JDK 25. Автоматизовані тести не замінюють ручної перевірки системного переміщення, resize та вигляду на реальних Windows, Linux і macOS.
