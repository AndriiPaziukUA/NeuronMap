# Власне оформлення головного вікна

## Єдиний механізм

NeuronMap використовує JDK 25 та JavaFX 27. Головне вікно створюється зі стилем `StageStyle.EXTENDED`, а власний заголовок розміщується в `javafx.scene.layout.HeaderBar`. Перед налаштуванням застосунок перевіряє `Platform.isSupported(ConditionalFeature.EXTENDED_WINDOW)`. Якщо можливість недоступна, конфігурація завершується явною помилкою: інший стиль вікна або резервний адаптер не запускається.

JavaFX відповідає за інтеграцію заголовка з віконною системою ОС, включно з переміщенням, системним resize і поведінкою семантичних кнопок. NeuronMap відповідає тільки за розташування заголовка, його стилі, локалізовані доступні назви кнопок і звичайний життєвий цикл застосунку.

У `WindowChromeView.installExtendedHeaderBar()` власним кнопкам призначаються ролі:

- `HeaderButtonType.ICONIFY` — згортання;
- `HeaderButtonType.MAXIMIZE` — максимізація та відновлення;
- `HeaderButtonType.CLOSE` — штатне закриття `Stage` через `WINDOW_CLOSE_REQUEST`.

Смуга заголовка допускає перетягування, але кнопки явно виключені з перетягуваної області за допомогою `HeaderDragType.NONE`. Тому кліки на них обробляються системним механізмом, а не саморобними mouse-filter-ами.

## Межі відповідальності

`MainWindowController` володіє `Stage`, відновленням геометрії та завершенням редактора. `WindowChromeLifecycle` перевіряє підтримку `EXTENDED_WINDOW`, установлює один стиль вікна, додає подання заголовка й звільняє його слухачі. `WindowChromeView` малює заголовок і підтримує локалізовані назви; він не обчислює hit-test-геометрію та не залежить від API конкретної ОС.

Пакети `com.example.neuronmap.window` і `com.example.neuronmap.windowing`, ручний Win32 `WndProc`, JNA-адаптери, ручний hit-testing і JavaFX fallback не використовуються. `persistence/window` залишається, бо відповідає лише за збереження геометрії. Для Windows, macOS і Linux застосовується той самий шлях JavaFX; окремі адаптери ОС для оформлення цього вікна не створюються.

## Перевірка

Запусти `./mvnw clean test` (у Windows — `.\mvnw.cmd clean test`). Окремо перевір на кожній цільовій ОС:

- переміщення за вільну область заголовка;
- зміну розміру за краями та кутами вікна;
- згортання, максимізацію/відновлення, закриття й збереження геометрії;
- доступність системних можливостей ОС, зокрема Snap Layouts у Windows 11;
- масштаби дисплея 100%, 125% і 150%, а також перетягування між моніторами з різним DPI.

Unit-тести перевіряють вибір єдиного механізму, семантичні ролі кнопок, перетягувану область і явну відмову, коли можливість недоступна. Вони не замінюють ручної перевірки інтеграції на реальних Windows, macOS і Linux.
