# Автоматична перевірка CSS

CSS-перевірки запускаються через JUnit як частина звичайного Maven build.

```bash
./mvnw -Dtest=CssStylesheetParserTest,ComponentStylesheetIsolationTest,IndependentStylesheetArchitectureTest test
```

У Windows використовуйте `./mvnw.cmd` з відповідним синтаксисом PowerShell (`.\mvnw.cmd`). Повний набір перевірок CI запускається командою `clean verify` на Windows, Linux і macOS.

## Що саме контролюється

Тестовий адаптер `CssStylesheetParser` використовує бібліотеку `ph-css` для побудови CSS AST замість розбору вкладених правил регулярним виразом. Залежність має область `test`, тому не додається до runtime-залежностей застосунку. Парсер відхиляє синтаксичні помилки, а перевірки обходять стилеві правила також усередині вкладених контейнерів `@media` і `@supports`.

`ComponentStylesheetIsolationTest` рекурсивно перевіряє всі CSS-файли в `src/main/resources`, їх наявність у classpath, локальні імпорти, відсутність циклів імпорту та виходу шляхів за межі каталогу ресурсів. `app.css` має залишатися агрегатором імпортів без власних правил.

Для кожного селектора AST визначається компонентний клас-власник. Стандартні класи JavaFX, наприклад `scroll-bar`, `thumb`, `list-cell` і `viewport`, а також модифікатори стану на кшталт `selected` і `hover` не вважаються власниками. Один компонентний клас не можна оголошувати у двох різних CSS-файлах.

Винятки навмисно обмежені двома конкретними випадками. По-перше, сімейство `window-chrome.css`, `window-chrome-linux.css` і `window-chrome-macos.css` має явний перелік спільних класів, які платформні файли можуть перевизначати; сторонній CSS-файл не може претендувати на них. По-друге, глобальні JavaFX-класи `.root` і `.menu-button` мають фіксованих власників: `.root` — `editor-shell.css`, а `.menu-button` та його стан наведення — `neuron.css`. Тест перевіряє, що базові правила обох класів реально присутні, а інші файли не стають їхніми власниками. Це два явні винятки, а не загальне виключення стандартних класів JavaFX із перевірки.

Обидва архітектурні тестові класи використовують один і той самий CSS AST: перевірка виявляє повторні правила з однаковим селектором та набором декларацій, а також зберігає регресійні перевірки потрібних станів hover/focus.

## Межі перевірки

Це статичний архітектурний контроль, а не повна реалізація рушія JavaFX CSS. Він не моделює довільне runtime-дерево JavaFX і не доводить усі семантичні перетини будь-яких можливих селекторів. Також він не замінює перевірку, чи підтримує JavaFX конкретне значення кожної властивості `-fx-*`. Ці межі відокремлені від граматичного аналізу CSS і контракту власності класів компонентів; фактичне оформлення важливих UI-компонентів додатково перевіряється їхніми UI-тестами.
